# Animate 2D characters

Use one workflow and one visual acceptance record at two checkpoints. Connected pixels and valid files do not prove good animation.

For a repair, start with the observed symptom in [production lessons](references/germany-simulator-lessons.md), then read only its linked method. Locate the first failing stage: approved source, extraction/registration, deformation/correspondence, encoded export, or actual runtime selection/ownership. Repair that stage before expanding the sequence; keep unresolved coverage explicit.

Before choosing canvas/frame sizes or upscaling, read [resolution and upscaling](references/resolution-and-upscaling.md). Compare actual source detail, export cells and displayed physical pixels (CSS × DPR); inspect extreme poses at native close-up resolution before expanding the sequence. Clean source mattes first, preserve family scale and alpha, and prefer rebaking higher-resolution originals over enlarging a lossy atlas. `scripts/assess_resolution.py` reports sampling ratios, aspect, gutters and texture memory; it does not certify visual quality.

For a **new character that will speak**, read [speech-ready character authoring](references/speech-ready-character-authoring.md) before creating its views or action sheet. Plan visible mouths and speech ownership with the interaction, fit mouth profiles alongside the approved source poses, and prove closure and changing-pose articulation before expanding the family. Reuse the existing body/media owners and the same two-checkpoint visual gate.

For a game walk, run the [planted-foot speed assessment](references/painted-walking.md#calibrate-ground-speed-to-planted-feet) on the exact exported side-view frames and actual billboard scale before setting the distance per gait cycle. Inspect remaining shoe slide in the running game; a distance-driven clock alone does not prove foot planting.

For a **liquid painted action between sharp anchors**, use the [paired Gaussian action starter](references/paired-gaussian-actions.md). Separate holdable main poses from transition arcs; start with two or three approved stable inbetweens and add compatible bridges around limb crossings, changing proportions and prop handoffs. Native-image Gaussian texture patches transport full-resolution paint throughout each interval. A bounded spatial phase delay supplies the liquid quality, returning exactly to each key; owned props share one phase. Keep support and opacity stable, without positional wiggle, trails or pauses at intermediate keys. Its [flicker diagnosis](references/paired-gaussian-actions.md#diagnose-flicker-before-changing-the-look) separates timing, correspondence, coverage, shader-cache and readiness faults. Validate every actor and loop in the actual renderer; packaging checks cannot approve motion.

For a sprite gaining depth, a small volumetric turn, an accompanying Gaussian tunnel, or recorded-media mouth articulation, read [Gaussian transitions](references/gaussian-transitions.md). A painted relief and a 2D texture transport solve different tasks. Gaussian rendering alone does not supply missing views, limb motion or a character rig; retain the approved sprite, shared renderer and existing event owner.

For speech during a changing body/head pose, read [mouth registration through transformations](references/gaussian-transitions.md#keep-the-mouth-attached-through-transformations). Register the currently displayed source cell or paired endpoints, preserve local lip correspondence through inbetweens, transport both mouth axes through baked fields, inherit actor transforms, and preserve the simulation's body phase. Endpoint rectangles alone cannot establish consistency across animated poses.

For a painted mouth whose opening tears the cheeks, detaches from the original line or doubles an existing cavity, use the [connected lip surface](references/gaussian-transitions.md#deform-a-connected-painted-lip-surface) method when the source painting can be registered. Fit each character and pose's corners, lip curve, source cavity boundaries, opening contours, rounding and tooth exposure to its actual pixels. The same normalized media cues drive each pose's own profile; a shared slit or unrelated bridge cannot supply another painting's anatomy. Keep the exact source while speech is inactive, but let an owned closed cue compress a pre-open source to one closed lip line. Preserve attached corners and original alpha. Apply the existing visual acceptance gate to every affected character and pose interval; a fixed-portrait result does not approve changing-pose speech.

1. **Lock the character.** Inspect the actual asset and approved other states at native size. Record facing, timing, canvas, baseline and prop hand. For a new view or action, identify its approved direction anchor and distinguish anatomical left/right from screen left/right; [methods](references/methods.md) covers source and extraction diagnosis. Compare views at a shared figure height; lock shorts coverage, exposed skin, limb widths, socks and footwear. Rejected movement frames are not a new design.
2. **Prove the source poses.** Reuse intact artwork or generate only missing views/key poses with the available image-generation tool. Compare them with the locked reference before animation. Reject elongated legs, generic tube shading, smaller shoes, changed clothing or props. For walking, prove opposite contacts and passing poses before expanding the loop.
3. **Build the movement.** Use the simplest method preserving approved pixels; read [methods](references/methods.md). For painted walks, four-direction game sources and side↔up/down stop/turn/start paths, read [painted walking](references/painted-walking.md). Use actual rear/up artwork, accepted whole-body turns and a shared pivot. Move full thighs/garment hems from a connected waist/pelvis, alternate planted/swing feet, and preserve complete knees, socks and ankles. Use one scale and registration per family. Preserve accepted rows during a repair. Smoothing or recolouring cannot replace missing anatomy. Declare both playback rate and **distinct visual samples per movement cycle**: a 60 fps renderer displaying four held poses is still a four-pose flipbook. Add enough genuine inbetweens to make the largest pose transition and the final-to-first seam fluent at the intended game size. A connected, continuously evaluated rig or source-pixel deformation is suitable for small motion; a new action with moving limbs needs approved keys and connected inbetweens. Whole-body crossfades or optical flow that duplicates hands, smears faces, or snaps at its midpoint fail even when the frame count is high.
   For character movement attached to dialogue, routes, or scripted scenes, read [narrative action rigging](references/narrative-action-rigging.md) before building poses or wiring the runtime. Author the action sequence and event ownership first so the needed keys are known from the start.
   To add frames between existing anchors, read [dense sampling](references/dense-sampling.md). First distinguish a continuous rig from discrete painted keys. Resample an existing rig directly; use `scripts/morph_sequence.py` only for compatible keys with authored correspondences. Preserve duration and distance per cycle, exact key samples, and the closing interval. Compare equal-duration sparse/dense exports before choosing the shipping count.
4. **Analyze the exact export.** View every affected encoded frame at native size, enlarged on light/dark backgrounds, alongside the reference, and in ordered motion at the intended playback speed. Check loop wraparound and relevant state transitions. Keep a shared figure scale, baseline, and **transparent gutter around every atlas cell** so bilinear sampling cannot pull pixels from a neighboring frame. Inspect alpha after final encoding, including mobile exports; source-sheet spacing alone is insufficient. Apply [the visual acceptance gate](references/final-frame-analysis.md). Repair failures and repeat; unresolved findings and qualified passes block delivery/update. Show motion from these pixels. After an authorized update, fetch and inspect stored frames too.

The single gate covers **contour, texture, image continuity, anatomy and colour**, including identity, source proportions, rendering style, lighting, waist/shorts/thigh/knee/sock/foot joins, and occlusion. Inspect the user's reported defect directly; numerical geometry cannot waive it. Source comparison is required before accepting generated art and after encoding.

Use `scripts/audit_final_frame_analysis.py` to bind real image observations to current reference/frame/export hashes and complete affected-frame coverage. Its test is `scripts/self_test_final_frame_analysis.py --output-dir <temporary-directory>`. Add numerical diagnostics only to investigate a specific defect; avoid duplicate approval ledgers or universal anatomical thresholds. The helper verifies provenance/completeness, not the truth of visual judgments.

For character reactions and their game event hooks, read [interaction states](references/interaction-states.md), including its one-shot timing rule. For ChatGPT Pets, read [Pets integration](references/pets-integration.md) and the installed Pets skill. Use its actual validators; retain stable IDs, other approved states and activation; show final motion before upload. Existing session approvals apply. For optional interpolation, read [morphing](references/morphing.md) after endpoints pass. For the Germany Simulator vacation-character failures, read [Germany Simulator lessons](references/germany-simulator-lessons.md).

Use premultiplied-alpha filtering; clear hidden RGB at alpha zero. Hidden alpha-zero RGB in a generator preview is not a painted backdrop: composite on real light/dark backgrounds before deciding to chroma-key. Apply one final edge-local chroma cleanup when needed, avoiding cumulative despill or whole-image blur. Solid-background GIFs prevent misleading palette fringes; retain the transparent export. Use fresh preview filenames when clients cache them.

When a new method solves an observed failure, update its short instructions/limitations in the relevant reference, verify helpers changed and refresh the portable package. Keep failed experiments in case notes, not the default workflow.

When comparing another animation pipeline, read the [source-pinned upstream method assessment](references/upstream-methods.md) for transferable ideas and implementation limits; it is provenance, not another production workflow.
